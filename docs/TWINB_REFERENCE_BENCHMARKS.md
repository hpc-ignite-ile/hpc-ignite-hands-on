# ทดลอง Mesa กับอาคารตัวอย่าง EnergyPlus

บทนี้ใช้อาคารสาธารณะเพื่อเรียนรู้ว่าพฤติกรรมคนส่งผลต่อเครื่องปรับอากาศอย่างไร เริ่มจากอาคารห้าโซนก่อน ไม่ต้องใช้ไฟล์อาคารส่วนตัว

อ่าน [ภาพรวม Twin-B](../mini-innovation/06-twinb-heatlab-repository.md) และ [คำอธิบาย Bash](BASH_COMMAND_REFERENCE_TH.md) ก่อนลงมือ

## สิ่งที่ต้องพร้อม

- บัญชี LANTA และพื้นที่โครงการที่คุณมีสิทธิ์ใช้งาน
- สำเนาคลังบทเรียนนี้บนพื้นที่โครงการ
- EnergyPlus **25.1.0** พร้อมไฟล์ `Energy+.idd` และข้อมูลอากาศที่มากับโปรแกรม
- สภาพแวดล้อม Python ที่มี Mesa **3.5.1**, eppy และส่วนประกอบที่ตัวเชื่อมใช้

ใช้รุ่นเดียวกันทั้งไฟล์อาคารและโปรแกรม อย่าเปลี่ยนรุ่นระหว่างการเปรียบเทียบ ถ้ายังไม่มีโปรแกรมหรือสภาพแวดล้อม ให้เตรียมกับผู้สอนก่อน ไม่ใช้เส้นทางของคนอื่นแทน

ตัวอย่างต่อไปนี้รันจากโฟลเดอร์หลักของคลังบทเรียน ตรวจด้วย `pwd` และ `ls scripts slurm` ก่อนเริ่ม

## ขั้นที่ 1: กำหนดเส้นทางของคุณ

รันบน เครื่องรับส่งข้อมูล สำหรับขั้นดาวน์โหลด:

```bash
read -rp "โฟลเดอร์ติดตั้ง EnergyPlus 25.1.0: " ENERGYPLUS_HOME
read -rp "โฟลเดอร์สภาพแวดล้อม Python สำหรับ Twin-B: " TWINB_VENV
export ENERGYPLUS_HOME TWINB_VENV
test -x "$ENERGYPLUS_HOME/energyplus"
test -f "$ENERGYPLUS_HOME/Energy+.idd"
test -x "$TWINB_VENV/bin/python"
```

ถ้าการตรวจข้อใดไม่ผ่าน ให้แก้เส้นทางก่อนทำต่อ คำสั่งตรวจนี้ยังไม่ทดสอบการจำลอง

## ขั้นที่ 2: ดาวน์โหลดอาคารและอากาศ

```bash
bash scripts/fetch_twinb_benchmarks.sh
ls inputs
sha256sum -c inputs/SHA256SUMS
```

สคริปต์ดาวน์โหลดอาคารห้าโซนและอาคารโรงเรียนจาก [ชุดตัวอย่าง EnergyPlus 25.1.0](https://github.com/NatLabRockies/EnergyPlus/tree/v25.1.0/testfiles) พร้อมเก็บสัญญาอนุญาต สำหรับขั้นแรกจะใช้เฉพาะอาคารห้าโซนกับอากาศ Chicago ที่มากับโปรแกรม

ไฟล์ `SHA256SUMS` ใช้ตรวจว่าไฟล์ไม่เปลี่ยนระหว่างทดลอง ไม่ได้ยืนยันว่าแบบจำลองตรงกับอาคารจริง

## ขั้นที่ 3: ส่งงานหนึ่งวัน

กลับมาเชื่อมต่อ login host เข้าสู่โฟลเดอร์เดิม และกำหนด `ENERGYPLUS_HOME` กับ `TWINB_VENV` อีกครั้งถ้าเปิดหน้าต่างใหม่ จากนั้น:

```bash
read -rp "บัญชีโครงการสำหรับ Slurm: " LANTA_ACCOUNT
export LANTA_ACCOUNT
mkdir -p logs results
job_id=$(sbatch -A "$LANTA_ACCOUNT" -p compute-devel \
    --parsable slurm/twinb-reference.sbatch)
echo "$job_id"
squeue -j "$job_id"
```

อย่ารันไฟล์ `.sbatch` ด้วย `bash` เพราะจะเริ่มคำนวณบนเครื่องเข้าสู่ระบบ บทนี้เริ่มขอ CPU 1 คอร์ หน่วยความจำ 2 GiB และเวลาสูงสุด 30 นาที เป็นขอบเขตเริ่มทดลอง ไม่ใช่คำรับรองว่าจะพอกับทุกสภาพแวดล้อม

## ขั้นที่ 4: ตรวจผล

```bash
sacct -j "$job_id" -P \
  -o JobID,State,ExitCode,Elapsed,TotalCPU,AllocCPUS,MaxRSS
cat "logs/twinb-reference_${job_id}.out"
cat "logs/twinb-reference_${job_id}.err"
cat "results/${job_id}/comparison/qualification.json"
```

ต้องตรวจทั้งสามส่วน:

1. งานจบโดยไม่มีข้อผิดพลาดร้ายแรงของ EnergyPlus
2. กรณีอ่านค่าอย่างเดียวและกรณีคืนการควบคุมให้โปรแกรม ให้ผลตรงกับกรณีตั้งต้น
3. เมื่อส่งคำขอควบคุม ค่าที่ระบบใช้เปลี่ยนตามคำขอ และ Mesa เดินหนึ่งครั้งต่อช่วงเวลาของอาคาร

`qualification.json` ต้องระบุ `passed: true` หากไม่ผ่านให้หยุดอ่านเหตุผล ไม่เพิ่มเวลาหรือจำนวนคอร์เพื่อข้ามการตรวจ

ไฟล์ `trace.csv` ในโฟลเดอร์ย่อยแต่ละกรณีใช้ดูเวลา อุณหภูมิ และคำขอควบคุม ส่วน `eplusout.csv` ใช้ดูผลจาก EnergyPlus และ `time.txt` ใช้ดูเวลาและหน่วยความจำ

## ตัวแทนคนในบทนี้หมายถึงอะไร?

อาคารห้าโซนใช้ตัวแทน 50 ตัวที่ส่งคำขอปรับอุณหภูมิ กฎและความต้องการถูกสร้างขึ้นเพื่อฝึกทดลอง ไม่ใช่ข้อมูลสำรวจผู้ใช้อาคารจริง

ระบบคงความร้อนจากคนและตารางใช้งานเดิมของ EnergyPlus ไว้ จึงไม่ควรเพิ่มความร้อนจากคนซ้ำอีกใน Mesa กฎควบคุมแบบง่ายอาจใช้ไฟมากขึ้นได้ ไม่ได้ออกแบบให้ประหยัดไฟเสมอ

## ลองต่ออย่างมีขอบเขต

- เพิ่มจากหนึ่งวันเป็นสามวัน โดยปรับ `--days` ในสำเนาไฟล์งานของคุณ
- เปลี่ยนจำนวนตัวแทนโดยคงอาคารและข้อมูลอากาศเดิม
- เปรียบเทียบเวลาของงานเดียวกันซ้ำสามครั้ง
- ลองอาคารโรงเรียนเมื่ออ่านผลของอาคารเล็กเป็นแล้ว

อาคารตัวอย่างไม่ใช่อาคารไทยที่ปรับเทียบแล้ว การเปลี่ยนไฟล์อากาศอย่างเดียวไม่ได้เปลี่ยนขนาดเครื่องปรับอากาศหรือวัสดุให้เหมาะกับท้องถิ่น ผลนี้จึงใช้เรียนรู้ ไม่ใช้รับรองการออกแบบหรือการประหยัดพลังงานจริง
